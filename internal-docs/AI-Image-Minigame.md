# AI Image Minigame

A practice minigame where the player is shown a series of images and decides whether each one was made by AI. It's opened from the AI minigame entry on the desk. This doc explains the game screen: what it does, where its code lives, and how it's tested. The images and answers come from the backend, which is covered in [AI-Minigame.md](AI-Minigame.md).

## What it does

The screen is the page at `/ai-image`. It's drawn with Konva on a brown desk background, with HTML buttons on top:

| Part | Where | What it is |
| --- | --- | --- |
| Back arrow | Top left | The shared back button (see [Back-Confirmation.md](Back-Confirmation.md)) |
| Progress box | Top left | "Progress" and which image this is, like `2/5` |
| Speech bubble | Top middle | "Is this image generated by AI?", or the score at the end |
| Image frame | Middle | The current image, scaled to fit inside a white frame |
| **AI** / **Not AI** | Right | The two answer buttons (red and green) |
| Journal | Bottom left, tilted | A drawn journal with a "Journal" sticky note (decoration only) |
| Error message | Top middle | Only shown when a request to the backend fails |

### How to play

1. The images are loaded from the backend and the first one shows. Click **AI** or **Not AI**.
2. The guess is sent to the backend, which says whether it was right. The next image shows and the progress goes up. Repeat for every image.
3. After the last guess, the bubble says "You got 3/5 correct!". The image and answer buttons are replaced by:
   - **Play again:** starts over at the first image with a fresh score.
   - **Return to desk:** goes back to the desk.

The player isn't told which images they got wrong, only the total.

### Keeping score

The frontend never knows which images are AI. Each guess is sent on its own with `submitAiAnswer(id, isAi)`, and the backend answers `{ correct: true | false }`. The model counts the right guesses and shows the total after the last image. The backend doesn't keep score, so **Play again** just sets the count back to 0. The images are loaded once and aren't fetched again.

### Locking the buttons

**AI** and **Not AI** are disabled (and show a "not allowed" cursor) while:

- the current image is still loading, so the player can't answer an image they haven't seen, and
- a guess is being checked by the backend, so a double click can't send the same guess twice.

### When the backend fails

A message appears at the top of the screen (`LOAD_ERROR` / `ANSWER_ERROR` in `aiMinigameContent.ts`):

- **The images fail to load:** "Could not load the images". The answer buttons stay locked. Reload the page once the backend is running.
- **A guess fails to send:** "Could not check your answer. Try again." The player stays on the same image and that guess doesn't count. Clicking again retries it.

### Leaving

The back arrow opens the shared "Are You Sure?" popup while a game is in progress, since leaving loses the score so far. **Go Back** goes to the desk and **Stay** keeps the game where it was. Once the score is showing there's nothing left to lose, so the arrow goes straight to the desk.

### Progress

This is practice, so finishing it **doesn't** mark anything done on the desk, whatever the score.

### Placeholders

- **Images:** the backend serves five solid-color placeholder squares with made-up answers. To add real images, see [Adding or changing images](AI-Minigame.md#adding-or-changing-images).
- **Journal:** the journal drawing is only decoration. Nothing is added to the real Journal.

## Where the code is

Everything for the screen is in `frontend/src/`:

```
frontend/src/
├── services/
│   └── aiImage.ts                      ← data shapes, getAiImages() and submitAiAnswer() (calls the backend)
└── components/AI-Minigame/
    ├── aiMinigameView.tsx              ← draws the screen (display only)
    ├── aiMinigameModel.tsx             ← state, image loading, answering, scoring, errors, resizing, navigation
    ├── aiMinigameContent.ts            ← labels, error messages, colors, and where each part sits
    └── tests/
        └── aiMinigame.test.tsx
```

The files depend on each other in one direction, following the [File Structure Guide](File-Structure-Guide.md):

```
aiMinigameView.tsx  →  aiMinigameModel.tsx  →  services/aiImage.ts  →  backend /api/ai-images
                    →  aiMinigameContent.ts →  routes.ts (to navigate)
```

### Fits any window size

Positions in `aiMinigameContent.ts` are fractions of the window, measured to each part's **center**. Sizes are fractions of a size unit:

```ts
const sizeUnit = Math.min(size.width, size.height * 1.5);
```

So parts stay in place as the window changes shape, but stop growing once the window is more than 1.5 times wider than it is tall. `place()` in the model turns a layout box into pixels.

### Which file do I open?

| I want to... | Open |
| --- | --- |
| Use real images, or change which ones are AI | `backend/seed/aiImages.json` and `backend/data/images/` (see [AI-Minigame.md](AI-Minigame.md#adding-or-changing-images)) |
| Change how the frontend calls the backend | `services/aiImage.ts` (`getAiImages`, `submitAiAnswer`) |
| Change a label, the question, the score message, or an error message | `aiMinigameContent.ts` |
| Move or resize something, or change a color | `aiMinigameContent.ts` |
| Change what happens on an answer, a failed request, Play again, or leaving | `aiMinigameModel.tsx` |
| Mark the minigame done on the desk | `aiMinigameModel.tsx`, using `services/progress.ts` like the other activities |
| Change how the journal or buttons are drawn | `aiMinigameView.tsx` |

## How it's tested

Run the tests from `frontend/` with `npm test`.

| Test file | What it checks |
| --- | --- |
| `aiMinigame.test.tsx` | **Playing:** opens on image 1 with the question and progress, both answers move to the next image in order, and one request is sent per guess with that image's id and the guess. **Results:** all right, all wrong, and a mix are scored correctly, and the image and answers are swapped for Play again and Return to desk. Nothing is marked done on the desk. **Play again:** goes back to image 1 and scores the next game on its own. **Leaving:** Return to desk goes to the desk. Mid-game the back arrow asks first (Go Back leaves, Stay keeps the same image), and from the results it leaves without asking. **Locking:** answers are disabled until the first image loads, while the next one loads (and a click then doesn't skip an image), and while a guess is being checked (a double click sends only one request). **Errors:** a failed image load shows an error and keeps the answers locked, and a failed guess shows an error, stays on the same image, can be retried, and doesn't count toward the score. |
| `services/tests/aiImage.test.ts` | Each service function calls the right URL with the right method and body, escapes the id, and throws when the backend responds with an error. |

`aiMinigame.test.tsx` doesn't talk to the real backend. It replaces `getAiImages()` and `submitAiAnswer()` with a fake backend that has its own 5 images and answer key (`IMAGES` and `CORRECT_ANSWERS` in the test), so changing the real images never breaks it. The backend routes have their own tests (see [AI-Minigame.md](AI-Minigame.md#how-its-tested)).

The test also replaces every Konva shape with nothing, since jsdom has no canvas (see [Konva-Testing.md](Konva-Testing.md)). Instead, the view puts the bubble text, progress, and current image's `alt` in visually hidden HTML, which the test reads. The browser's `Image` is replaced with a fake whose loads the test can hold back and release, to check the button locking.

### What the tests can't check

These depend on drawing the screen or a running backend, so check them by hand with `npm run dev` from the repo root:

- [ ] Every part sits where the mockup shows at different window sizes, and nothing overlaps.
- [ ] The image is centered in the frame and not stretched.
- [ ] The journal drawing, its scribbles, and its sticky note look right.
- [ ] The answer buttons show a "not allowed" cursor while disabled.
- [ ] The back arrow is visible in the top left corner.
- [ ] The placeholder images from the backend show in the frame, and guessing AI, Not AI, AI, Not AI, AI gets 5/5.
- [ ] With the backend stopped, opening the game shows "Could not load the images".

### Known limitations

- The model loads each image with its own `new Image()` instead of the shared `URLImage` component. There's a TODO to switch over now that the title screen branch is merged.
- The placeholder images are solid colors, so there's nothing to actually tell apart yet.
- Text is drawn in Arial, not the game's Coiny font.
