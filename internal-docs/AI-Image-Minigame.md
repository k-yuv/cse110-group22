# AI Image Minigame

A practice minigame where the player is shown a series of images and decides whether each one was made by AI. It's opened from the AI minigame entry on the desk. This doc explains what it does, where its code lives, and how it's tested.

## What it does

The screen is the page at `/ai-image`. It's drawn with Konva on a brown desk background, with HTML buttons on top:

| Part | Where | What it is |
| --- | --- | --- |
| Progress box | Top left | "Progress" and which image this is, like `2/5` |
| Speech bubble | Top middle | "Is this image generated by AI?", or the score at the end |
| Image frame | Middle | The current image, scaled to fit inside a white frame |
| **AI** / **Not AI** | Right | The two answer buttons (red and green) |
| Journal | Bottom left, tilted | A drawn journal with a "Journal" sticky note (decoration only) |
| Back arrow | Bottom right | Returns to the desk at any time |

### How to play

1. The first image shows. Click **AI** or **Not AI**.
2. The next image shows and the progress goes up. Repeat for every image.
3. After the last answer, the answers are scored together and the bubble says "You got 3/5 correct!". The image and answer buttons are replaced by:
   - **Play again:** starts over at the first image with a fresh score.
   - **Return to desk:** goes back to the desk.

The player isn't told which images they got wrong, only the total.

### Locking the buttons

**AI** and **Not AI** are disabled (and show a "not allowed" cursor) while:

- the current image is still loading, so the player can't answer an image they haven't seen, and
- the answers are being scored, so they're only scored once.

### Progress

This is practice, so finishing it **doesn't** mark anything done on the desk, whatever the score.

### Mocks and placeholders

- **Images:** `services/aiImage.ts` returns five solid-color placeholder squares from `getAiImages()`. Each has an `id`, a `src`, and `alt` text.
- **Scoring:** `checkAiAnswers()` in the same file holds the answer key and counts the right answers. Both functions are async like real requests, so moving the images and answer key to a backend only changes these two functions. The answer key never has to reach the view.
- **Journal:** the journal drawing is only decoration. Nothing is added to the real Journal.

## Where the code is

Everything is in `frontend/src/`:

```
frontend/src/
├── services/
│   └── aiImage.ts                      ← data shapes, placeholder images, answer key, getAiImages(), checkAiAnswers()
└── components/AI-Minigame/
    ├── aiMinigameView.tsx              ← draws the screen (display only)
    ├── aiMinigameModel.tsx             ← state, image loading, answering, scoring, resizing, navigation
    ├── aiMinigameContent.ts            ← labels, colors, and where each part sits
    └── tests/
        └── aiMinigame.test.tsx
```

The files depend on each other in one direction, following the [File Structure Guide](File-Structure-Guide.md):

```
aiMinigameView.tsx  →  aiMinigameModel.tsx  →  services/aiImage.ts
                    →  aiMinigameContent.ts →  routes.ts (to navigate)
```

### Fits any window size

Positions in `aiMinigameContent.ts` are fractions of the window, measured to each part's **center**. Sizes are fractions of a size unit:

```ts
const sizeUnit = Math.min(size.width, size.height * 1.5);
```

So parts stay in place as the window changes shape, but stop growing once the window is more than 1.5 times wider than it is tall. `place()` in the model turns a layout box into pixels.

### Which file do I open?

| I want to... | Open |
| --- | --- |
| Use real images, or change which ones are AI | `services/aiImage.ts` (`DEFAULT_IMAGES`) |
| Connect to a real backend route | `services/aiImage.ts` (`getAiImages`, `checkAiAnswers`) |
| Change a label, the question, or the score message | `aiMinigameContent.ts` |
| Move or resize something, or change a color | `aiMinigameContent.ts` |
| Change what happens on an answer, Play again, or leaving | `aiMinigameModel.tsx` |
| Mark the minigame done on the desk | `aiMinigameModel.tsx`, using `services/progress.ts` like the other activities |
| Change how the journal or buttons are drawn | `aiMinigameView.tsx` |

### Adding images

- Put image files in `frontend/src/assets/` and import them in `services/aiImage.ts` for `src`.
- Give every image a unique `id` and a short `alt` description. Screen readers and the tests use `alt`.
- `isAi` is the answer. Keep it in the service, never in the view or model.
- Images of any shape work. They're scaled down to fit the frame without stretching.

## How it's tested

Run the tests from `frontend/` with `npm test`.

| Test file | What it checks |
| --- | --- |
| `aiMinigame.test.tsx` | **Playing:** opens on image 1 with the question and progress, and both answers move to the next image in order. **Results:** all right, all wrong, and a mix are scored correctly, and the image and answers are swapped for Play again and Return to desk. Nothing is marked done on the desk. **Play again:** goes back to image 1 and scores the next game on its own. **Leaving:** Return to desk and the back arrow (mid-game and from results) go to the desk. **Locking:** answers are disabled until the first image loads, while the next one loads (and a click then doesn't skip an image), and while scoring, which only happens once. |

The test replaces every Konva shape with nothing, since jsdom has no canvas (see [Konva-Testing.md](Konva-Testing.md)). Instead, the view puts the bubble text, progress, and current image's `alt` in visually hidden HTML, which the test reads. The browser's `Image` is replaced with a fake whose loads the test can hold back and release, to check the button locking. Image ids and answers come from `getAiImages()` instead of being typed out, so the test expects the answer key `[true, false, true, false, true]`. If you change which placeholder images are AI, update `CORRECT_ANSWERS` in the test.

### What the tests can't check

These depend on drawing the screen, so check them by hand with `npm run dev`:

- [ ] Every part sits where the mockup shows at different window sizes, and nothing overlaps.
- [ ] The image is centered in the frame and not stretched.
- [ ] The journal drawing, its scribbles, and its sticky note look right.
- [ ] The answer buttons show a "not allowed" cursor while disabled.
- [ ] The back arrow is visible in the bottom right corner.

### Known limitations

- The model loads each image with its own `new Image()` instead of the shared `URLImage` component. There's a TODO to switch over now that the title screen branch is merged.
- The placeholder images are solid colors, so there's nothing to actually tell apart yet.
- Text is drawn in Arial, not the game's Coiny font.
