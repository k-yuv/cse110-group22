# AI Image Minigame

A practice minigame where the player is shown a series of images and guesses whether each one was made by AI. It's opened from the AI minigame entry on the desk. The images and the answers live on the backend, so players can't find the answers in the frontend code. This doc explains what the minigame does, how the screen and backend work together, how to add images, where the code lives, and how it's tested.

## What it does

The screen is the page at `/ai-image`. It's drawn with Konva on a brown desk background, with HTML buttons on top:

| Part | Where | What it is |
| --- | --- | --- |
| Back arrow | Top left | The shared back button (see [Back-Confirmation.md](Back-Confirmation.md)) |
| Progress box | Top left | "Progress" and which image this is, like `2/5` |
| Speech bubble | Top middle | "Is this image generated by AI?", or the score at the end |
| Image frame | Middle | The current image, scaled to fit inside a white frame |
| **AI** / **Not AI** | Right | The two answer buttons (red and green) |
| Journal | Bottom left, tilted | A drawn journal with a "Journal" sticky note. It's only decoration, and nothing is added to the real Journal. |
| Error message | Top middle | Only shown when a request to the backend fails |

### How to play

1. The images are loaded from the backend and the first one shows. Click **AI** or **Not AI**.
2. The guess is sent to the backend, which says whether it was right. The next image shows and the progress goes up. Repeat for every image.
3. After the last guess, the bubble says "You got 3/5 correct!". The image and answer buttons are replaced by:
   - **Play again:** starts over at the first image with a fresh score. The images aren't fetched again.
   - **Return to desk:** goes back to the desk.

The player isn't told which images they got wrong, only the total.

This is practice, so finishing it **doesn't** mark anything done on the desk, whatever the score.

### Talking to the backend

The backend has two routes for the minigame, and `frontend/src/services/aiImage.ts` has one function for each:

| Route | Function | When it's called |
| --- | --- | --- |
| `GET /api/ai-images` | `getAiImages()` | Once, when the screen opens |
| `POST /api/ai-images/:id/answers` | `submitAiAnswer(id, isAi)` | Each time the player clicks **AI** or **Not AI** |

The picture files themselves are served from `GET /api/images/<fileName>`.

`GET /api/ai-images` lists every image, in the order they're shown:

```json
[
  { "id": "img-1", "src": "/api/images/cat-1.jpg", "alt": "Close-up of an orange tabby cat's face" },
  { "id": "img-2", "src": "/api/images/cat-2.jpg", "alt": "Close-up of a tabby and white cat with blue eyes" }
]
```

| Field | What it is |
| --- | --- |
| `id` | Used to submit a guess for this image |
| `src` | URL to load the picture from. Put it straight into an `<img>` or `new Image()`. |
| `alt` | Text description of the picture, for screen readers |

**The list never says which images are AI.** Instead, each guess is sent on its own:

```
POST /api/ai-images/img-1/answers
{ "isAi": true }
```

`isAi: true` means the player thinks the image **is** AI-generated. The backend answers whether the guess was right:

| Response | When |
| --- | --- |
| `200` `{ "correct": true \| false }` | The image exists |
| `404` `{ "error": "Image not found" }` | No image has that id |
| `400` | `isAi` is missing or not a boolean, or the body has extra fields |

### Keeping score

**The backend doesn't keep score.** Each guess is checked on its own and nothing is saved. `aiMinigameModel.tsx` keeps the score instead. On each click it:

1. Locks the **AI** / **Not AI** buttons.
2. Sends the guess and adds 1 to the score if the response says `correct: true`.
3. Moves to the next image. After the last image, it shows "You got X/Y correct!".

**Play again** sets the score back to 0.

### Locking the buttons

**AI** and **Not AI** are disabled (and show a "not allowed" cursor) while:

- the current image is still loading, so the player can't answer an image they haven't seen, and
- a guess is being checked by the backend, so a double click can't send the same guess twice.

### When the backend fails

A message appears at the top of the screen (`LOAD_ERROR` / `ANSWER_ERROR` in `aiMinigameContent.ts`):

- **The images fail to load:** "Could not load the images". The answer buttons stay locked. Reload the page once the backend is running.
- **A guess fails to send:** "Could not check your answer. Try again." The player stays on the same image and that guess doesn't count. Clicking again retries it.

### Leaving

The back arrow opens the shared "Are You Sure?" popup while a game is in progress, since leaving loses the score so far. **Go Back** goes to the desk and **Stay** keeps the game where it was. Once the score is showing there's nothing left to lose, so the arrow goes straight to the desk.

### Where the images live

The images are stored like a tiny database: a JSON "table" of images, plus a folder with the picture files. Each entry in the table refers to its picture **by file name**.

| What | Where | Committed to git? |
| --- | --- | --- |
| The picture files | `backend/data/images/` | **Yes** (the one exception in `backend/data/`, see `.gitignore`) |
| The image table (starter copy) | `backend/seed/aiImages.json` | Yes |
| The image table the backend reads | `backend/data/aiImages.json` | No. It's copied from `seed/` when the backend starts (see [Bare-Essentials.md](Bare-Essentials.md#starter-data-backendseed)). |

Each entry in the image table looks like this:

```json
{ "id": "img-1", "fileName": "cat-1.jpg", "alt": "Close-up of an orange tabby cat's face", "isAi": true }
```

| Field | What it is |
| --- | --- |
| `id` | Unique id for the image. Any short string, e.g. `img-6`. |
| `fileName` | Name of the picture file in `backend/data/images/` |
| `alt` | Text description, for screen readers. Don't give away the answer. |
| `isAi` | `true` if the image was generated by AI. **Never sent to the frontend.** |

Before sending the list, the backend turns `fileName` into `src` (`/api/images/<fileName>`) and removes `isAi`.

### Only works on localhost

Images are plain files served by the backend. The `/api/images/...` URLs work in the browser because Vite forwards everything under `/api` to the backend (see `frontend/vite.config.ts`). Nothing here is set up for deployment.

## Adding or changing images

1. Put the picture file in `backend/data/images/` (any format the browser can show: `.jpg`, `.png`, `.webp`, `.svg`, ...).
2. Add an entry for it in `backend/seed/aiImages.json`, with `fileName` set to the file's exact name (including the extension).
3. Stop the backend, **delete `backend/data/aiImages.json`**, and start it again so it copies the new seed file. (Seeding never overwrites a data file that already has something in it.)
4. Add the image to [The current images](#the-current-images) with its source and license.
5. Commit the picture file, the seed file and this doc. In the PR description, tell everyone to delete their `backend/data/aiImages.json`.

The order of entries in the table is the order the player sees the images.

**Don't let the file give the answer away.** The player's browser downloads every picture and can see its URL, so:

- Use neutral file names like `cat-6.jpg`, never `ai-cat.jpg`.
- Save every image in the same format. If the AI images are `.png` and the real ones `.jpg`, the extension gives the answer away.
- Strip the metadata. Real photos often carry camera EXIF data, and AI images can carry generator tags. Re-saving the picture as a fresh JPEG removes both. The current images were re-saved this way, at most 800px wide.

> [!TIP]
> A test checks that every `fileName` in `seed/aiImages.json` has a matching file in `backend/data/images/`, so a typo in a file name fails `npm test`.

The files depend on each other in one direction, following the [File Structure Guide](File-Structure-Guide.md):

```
aiMinigameView.tsx  →  aiMinigameModel.tsx  →  services/aiImage.ts  →  (HTTP)  →  aiImages.router.ts
                    →  aiMinigameContent.ts →  routes.ts (to navigate)

aiImages.router.ts  →  aiImages.controller.ts  →  aiImages.service.ts  →  utils/jsonStore.ts
                                                                       →  utils/images.ts
```

### Fits any window size

Positions in `aiMinigameContent.ts` are fractions of the window, measured to each part's **center**. Sizes are fractions of a size unit:

```ts
const sizeUnit = Math.min(size.width, size.height * 1.5);
```

So parts stay in place as the window changes shape, but stop growing once the window is more than 1.5 times wider than it is tall. `place()` in the model turns a layout box into pixels.

### Which file do I open?

| I want to... | Open |
| --- | --- |
| Add, remove, or reorder images, or change an answer | `backend/seed/aiImages.json` and `backend/data/images/` (see [Adding or changing images](#adding-or-changing-images)) |
| Change a label, the question, the score message, or an error message | `aiMinigameContent.ts` |
| Move or resize something, or change a color | `aiMinigameContent.ts` |
| Change what happens on an answer, a failed request, Play again, or leaving | `aiMinigameModel.tsx` |
| Change how the journal or buttons are drawn | `aiMinigameView.tsx` |
| Mark the minigame done on the desk | `aiMinigameModel.tsx`, using `services/progress.ts` like the other activities |
| Change how the frontend calls the backend | `frontend/src/services/aiImage.ts` |
| Change what a route accepts or returns | `backend/openapi.yaml` first, then the types in `app.ts` and `services/aiImage.ts` |
| Change how a guess is checked | `aiImages.service.ts` (`checkAnswer`) |
| Change a status code or backend error message | `aiImages.controller.ts` |
| Move the picture folder or change its URL | `backend/src/utils/images.ts` |

## How it's tested

Run the tests with `npm test`, from `frontend/` for the screen and from `backend/` for the routes.

### Frontend

| Test file | What it checks |
| --- | --- |
| `components/AI-Minigame/tests/aiMinigame.test.tsx` | **Playing:** opens on image 1 with the question and progress, both answers move to the next image in order, and one request is sent per guess with that image's id and the guess. **Results:** all right, all wrong, and a mix are scored correctly, and the image and answers are swapped for Play again and Return to desk. Nothing is marked done on the desk. **Play again:** goes back to image 1 and scores the next game on its own. **Leaving:** Return to desk goes to the desk. Mid-game the back arrow asks first (Go Back leaves, Stay keeps the same image), and from the results it leaves without asking. **Locking:** answers are disabled until the first image loads, while the next one loads (and a click then doesn't skip an image), and while a guess is being checked (a double click sends only one request). **Errors:** a failed image load shows an error and keeps the answers locked, and a failed guess shows an error, stays on the same image, can be retried, and doesn't count toward the score. |
| `services/tests/aiImage.test.ts` | Each function calls the right URL with the right method and body, escapes the id, and throws when the backend responds with an error. |

`aiMinigame.test.tsx` doesn't talk to the real backend. It replaces `getAiImages()` and `submitAiAnswer()` with a fake backend that has its own 5 images and answer key (`IMAGES` and `CORRECT_ANSWERS` in the test), so changing the real images never breaks it.

It also replaces every Konva shape with nothing, since jsdom has no canvas (see [Konva-Testing.md](Konva-Testing.md)). Instead, the view puts the bubble text, progress, and current image's `alt` in visually hidden HTML, which the test reads. The browser's `Image` is replaced with a fake whose loads the test can hold back and release, to check the button locking.

### Backend

`features/aiImages/tests/aiImages.test.ts` reads the image table from `backend/data/test/aiImages.json`, so it never touches your real data. The picture files are only read, never changed, so it uses the real `backend/data/images/` folder.

| Test | What it checks |
| --- | --- |
| Listing | Every image in order with `id`, `src` and `alt`, and **no `isAi`**. File names with spaces or `#` are escaped in `src`. An empty list if the table doesn't exist yet. `500` if the table isn't valid JSON. |
| Picture files | Every listed `src` loads as an image. Every `fileName` in `seed/aiImages.json` exists in `data/images/`. A missing file responds `404`. |
| Guessing | Right and wrong guesses for both AI and real images. Nothing in the table changes. `404` for an unknown id or a missing table. `400` for an `isAi` that's missing, a string, a number, `null`, or has extra fields next to it. `415` with no body. `405` for `GET`. `500` if the table isn't valid JSON. |

`src/tests/seed.test.ts` also clears `aiImages.json` before each test, since starting the backend seeds every file in `backend/seed/`.

### What the tests can't check

These depend on drawing the screen or a running backend, so check them by hand with `npm run dev` from the repo root:

- [ ] Every part sits where the mockup shows at different window sizes, and nothing overlaps.
- [ ] The image is centered in the frame and not stretched.
- [ ] The journal drawing, its scribbles, and its sticky note look right.
- [ ] The answer buttons show a "not allowed" cursor while disabled.
- [ ] The back arrow is visible in the top left corner.
- [ ] The cat pictures from the backend show in the frame, and guessing AI, Not AI, AI, Not AI, AI gets 5/5.
- [ ] With the backend stopped, opening the game shows "Could not load the images".

### Known limitations

- The model loads each image with its own `new Image()` instead of the shared `URLImage` component. There's a TODO to switch over now that the title screen branch is merged.
- Text is drawn in Arial, not the game's Coiny font.
