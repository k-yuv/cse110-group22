# AI Minigame

In the AI image guessing minigame, the player is shown a series of images and guesses whether each one was generated by AI. This doc explains what the backend for it does, how the game screen uses it, where the code and images live, how to add images, and how it's tested.

## What it does

The game screen is the page at `/ai-image` (`frontend/src/components/AI-Minigame/`). The backend gives it two routes:

| Route | What it does |
| --- | --- |
| `GET /api/ai-images` | Lists every image, in the order they should be shown |
| `POST /api/ai-images/:id/answers` | Checks one guess and says whether it was right |

The picture files themselves are served from `GET /api/images/<fileName>`.

### Getting the images

`GET /api/ai-images` responds with a list like this:

```json
[
  { "id": "img-1", "src": "/api/images/placeholder-1.svg", "alt": "Placeholder image 1 (pink)" },
  { "id": "img-2", "src": "/api/images/placeholder-2.svg", "alt": "Placeholder image 2 (blue)" }
]
```

| Field | What it is |
| --- | --- |
| `id` | Used to submit a guess for this image |
| `src` | URL to load the picture from. Put it straight into an `<img>` or `new Image()`. |
| `alt` | Text description of the picture, for screen readers |

**The response never says which images are AI.** That's only checked on the backend, so players can't find the answers by looking at network requests or frontend code.

### Submitting a guess

The player answers one image at a time. Send the guess for that image:

```
POST /api/ai-images/img-1/answers
{ "isAi": true }
```

`isAi: true` means the player thinks the image **is** AI-generated. The response says whether the guess was right:

```json
{ "correct": true }
```

| Response | When |
| --- | --- |
| `200` `{ "correct": true \| false }` | The image exists |
| `404` `{ "error": "Image not found" }` | No image has that id |
| `400` | `isAi` is missing or not a boolean, or the body has extra fields |

**The backend doesn't keep score.** Each guess is checked on its own and nothing is saved. The frontend counts the `correct: true` responses to track the player's accuracy (e.g. "You got 4/5 correct!").

### Where the images live

The images are stored like a tiny database: a JSON "table" of images, plus a folder with the picture files. Each entry in the table refers to its picture **by file name**.

| What | Where | Committed to git? |
| --- | --- | --- |
| The picture files | `backend/data/images/` | **Yes** (the one exception in `backend/data/`, see `.gitignore`) |
| The image table (starter copy) | `backend/seed/aiImages.json` | Yes |
| The image table the backend reads | `backend/data/aiImages.json` | No. It's copied from `seed/` when the backend starts (see [Bare-Essentials.md](Bare-Essentials.md#starter-data-backendseed)). |

Each entry in the image table looks like this:

```json
{ "id": "img-1", "fileName": "placeholder-1.svg", "alt": "Placeholder image 1 (pink)", "isAi": true }
```

| Field | What it is |
| --- | --- |
| `id` | Unique id for the image. Any short string, e.g. `img-6`. |
| `fileName` | Name of the picture file in `backend/data/images/` |
| `alt` | Text description, for screen readers. Don't give away the answer. |
| `isAi` | `true` if the image was generated by AI. **Never sent to the frontend.** |

Before sending the list, the backend turns `fileName` into `src` (`/api/images/<fileName>`) and removes `isAi`.

### Placeholder images

There are no real images yet. The 5 images are colored squares (`placeholder-1.svg` to `placeholder-5.svg`) with made-up `isAi` answers.

### Only works on localhost

Images are plain files served by the backend. The `/api/images/...` URLs work in the browser because Vite forwards everything under `/api` to the backend (see `frontend/vite.config.ts`). Nothing here is set up for deployment.

## Adding or changing images

1. Put the picture file in `backend/data/images/` (any format the browser can show: `.jpg`, `.png`, `.webp`, `.svg`, ...).
2. Add an entry for it in `backend/seed/aiImages.json`, with `fileName` set to the file's exact name (including the extension).
3. Stop the backend, **delete `backend/data/aiImages.json`**, and start it again so it copies the new seed file. (Seeding never overwrites a data file that already has something in it.)
4. Commit both the picture file and the seed file. In the PR description, tell everyone to delete their `backend/data/aiImages.json`.

The order of entries in the table is the order the player sees the images.

> [!TIP]
> A test checks that every `fileName` in `seed/aiImages.json` has a matching file in `backend/data/images/`, so a typo in a file name fails `npm test`.

## Where the code is

```
backend/
├── openapi.yaml                    ← the two routes and the AiImage / NewAiAnswer schemas
├── seed/
│   └── aiImages.json               ← the image table (starter copy)
├── data/
│   └── images/                     ← the picture files (committed)
└── src/
    ├── app.ts                      ← AiImage / StoredAiImage types, mounts the router and serves /api/images
    ├── utils/
    │   └── images.ts               ← where the picture folder is, and the URL it's served at
    └── features/aiImages/
        ├── aiImages.router.ts      ← maps the two URLs to the controller
        ├── aiImages.controller.ts  ← reads the request, picks the status code
        ├── aiImages.service.ts     ← reads the table, builds src, checks guesses
        └── tests/
            └── aiImages.test.ts
```

The files follow the backend pattern in the [File Structure Guide](File-Structure-Guide.md):

```
aiImages.router.ts  →  aiImages.controller.ts  →  aiImages.service.ts  →  utils/jsonStore.ts
                                                                       →  utils/images.ts
```

### Which file do I open?

| I want to... | Open |
| --- | --- |
| Add, remove, or reorder images, or change an answer | `backend/seed/aiImages.json` and `backend/data/images/` (see [Adding or changing images](#adding-or-changing-images)) |
| Change what a route accepts or returns | `backend/openapi.yaml` first, then the types in `app.ts` |
| Change how a guess is checked | `aiImages.service.ts` (`checkAnswer`) |
| Change the status code or error message | `aiImages.controller.ts` |
| Move the picture folder or change its URL | `utils/images.ts` |
| Change how the frontend calls these routes | `frontend/src/services/aiImage.ts` |
| Change how the frontend keeps score or handles a failed request | `frontend/src/components/AI-Minigame/aiMinigameModel.tsx` (`handleAnswer`) |

### How the frontend uses it

`frontend/src/services/aiImage.ts` has one function per route:

| Function | Route |
| --- | --- |
| `getAiImages()` | `GET /api/ai-images`, called once when the screen opens |
| `submitAiAnswer(id, isAi)` | `POST /api/ai-images/:id/answers`, called each time the player clicks **AI** or **Not AI** |

`aiMinigameModel.tsx` keeps the score. On each click it:

1. Locks the **AI** / **Not AI** buttons, so a double click can't send the same guess twice.
2. Sends the guess and adds 1 to the score if the response says `correct: true`.
3. Moves to the next image. After the last image, it shows "You got X/Y correct!".

**Play again** sets the score back to 0. The images are loaded once and aren't fetched again.

If a request fails, a message appears at the top of the screen (`LOAD_ERROR` / `ANSWER_ERROR` in `aiMinigameContent.ts`):

- **The images fail to load:** the buttons stay locked. Reload the page once the backend is running.
- **A guess fails to send:** the player stays on the same image, and that guess doesn't count. Clicking again retries it.

## How it's tested

Run the tests from `backend/` with `npm test`. They read the image table from `backend/data/test/aiImages.json`, so they never touch your real data. The picture files are only read, never changed, so the tests use the real `backend/data/images/` folder.

| Test | What it checks |
| --- | --- |
| Listing | Every image in order with `id`, `src` and `alt`, and **no `isAi`**. File names with spaces or `#` are escaped in `src`. An empty list if the table doesn't exist yet. `500` if the table isn't valid JSON. |
| Picture files | Every listed `src` loads as an image. Every `fileName` in `seed/aiImages.json` exists in `data/images/`. A missing file responds `404`. |
| Guessing | Right and wrong guesses for both AI and real images. Nothing in the table changes. `404` for an unknown id or a missing table. `400` for an `isAi` that's missing, a string, a number, `null`, or has extra fields next to it. `415` with no body. `405` for `GET`. `500` if the table isn't valid JSON. |

`src/tests/seed.test.ts` also clears `aiImages.json` before each test, since starting the backend seeds every file in `backend/seed/`.

On the frontend (`npm test` from `frontend/`):

| Test file | What it checks |
| --- | --- |
| `services/tests/aiImage.test.ts` | Each function calls the right URL with the right method and body, escapes the id, and throws when the backend responds with an error. |
| `components/AI-Minigame/tests/aiMinigame.test.tsx` | Uses a fake backend (its own 5 images and answers), so it doesn't depend on the real data. **One request is sent per guess, with that image's id and the guess.** The score after all-right, all-wrong and mixed guesses. Buttons lock while a guess is being checked, and a double click sends only one request. Load and send errors, retrying a failed guess, and a failed guess not counting. |

### What the tests can't check

Check these by hand with `npm run dev` from the repo root:

- [ ] The game at `/ai-image` shows the placeholder images in the frame.
- [ ] Clicking through all 5 shows the right score (with the placeholders, guessing AI, Not AI, AI, Not AI, AI gets 5/5).
- [ ] With the backend stopped, opening the game shows "Could not load the images".
